# 선행 연구 조사 — 우리 회계는 새롭지 않다

`PAPER.md` 의 첫 할 일이 이것이었다. 했고, **novelty 주장이 크게 약해졌다.**

**주의: 논문 본문을 읽지 않고 검색 결과 요약으로 판단했다.**
원문 대조 전까지 아래 내용도 미검증이다.

## 1. 회계 원리 자체는 표준이다

| | |
|---|---|
| **MDL / Kolmogorov** | 모델 + 데이터의 **총 기술 길이**로 재는 것은 수십 년 된 표준이다. Shannon–Solomonoff–Kolmogorov 로 거슬러 올라간다 |
| **Practical Kolmogorov optimality** | 데이터셋을 (모델, 잔차) 쌍으로 부호화하고 **모델 비용을 포함한 총 기술 길이**를 재는 프레임워크. 우리가 쓴 식이 여기 형식화돼 있다 |

**우리가 "제안" 한 총전송량 식은 MDL 의 특수한 경우다.** 새로 만든 것이 아니다.

## 2. 학습 압축 분야에서 이미 실제로 쓰인다

**L3TC** (텍스트 무손실 압축):

> gzip 대비 50% 절약, 그리고 **모델 크기를 계산에 넣었을 때** 다른 학습
> 압축기 대비 48% 더 절약

모델 크기를 회계에 넣어 비교했다는 뜻이다. 그리고 같은 맥락에서
**"저비트 양자화를 해도 모델 크기 오버헤드가 여전히 커서 실배포가 어렵다"**
는 지적이 이미 나와 있다. 우리가 발견한 것과 같은 결론이다.

**LMCompress 비판:** *"거대한 모델·자원비용·느린 속도 때문에 실사용
시나리오에서 쓸 수 없다"* — 같은 비판이 이미 제기돼 있다.

## 3. 오디오 코덱 논문도 모델 크기를 보고한다

DualCodec 의 비교표에 이미 들어 있다:

| | 파라미터 | 프레임률 |
|---|---|---|
| DAC | 74M | 75 Hz |
| EnCodec | 15M | 75 Hz |
| SpeechTokenizer | 103M | |
| WavTokenizer-large | 71M | |
| Mimi | 78M | 12.5 Hz |

TS3-Codec 은 GMACs 까지 보고한다 (Mimi 8.1G GMACs / 79.3M).

**즉 "모델 크기를 안 쓴다" 는 우리 전제부터 틀렸다.** 다만 **복잡도(연산량·메모리)
지표로 쓰지, 전송 비용으로 환산해 비트레이트와 합산하지는 않는다.**

## 그래서 무엇이 남는가

| 우리가 하려던 주장 | 상태 |
|---|---|
| "모델 크기를 회계에 넣어야 한다" | **이미 표준 (MDL)** |
| "학습 압축기에서 모델 오버헤드가 문제다" | **이미 지적됨 (L3TC, LMCompress 비판)** |
| "코덱 논문이 모델 크기를 보고하지 않는다" | **틀렸다. 보고한다** |
| **손익분기를 시간 단위로 환산** | 못 찾았다. 다만 없다는 증거는 아니다 |
| **압축률 순위와 총전송량 순위의 역전을 실측** | 못 찾았다. 같음 |

**남는 것은 "알려진 회계를 손실 오디오 코덱에 적용해 순위 역전을 보인 것"**
정도다. 원리가 새로운 것이 아니라 **적용 영역과 구체적 수치**만 새롭다.

논문이라면 방법론 논문이 아니라 **분석·벤치마크 보고**가 맞다.
그리고 "우리가 제안한다" 가 아니라 **"MDL 관점을 이 분야에 적용하면"** 으로
써야 한다.

## 조사하면서 나온 개선점 하나

**수신자는 디코더만 있으면 된다.** 우리는 체크포인트 전체(인코더+양자화기
+디코더)를 모델 비용으로 넣었는데, 단방향 전송이라면 **디코더 크기만**
계산해야 한다.

그리고 비대칭 설계가 실제로 존재한다 — **XCodec2 는 인코더가 디코더보다
훨씬 크다.** 이런 코덱은 수신 측 손익분기가 우리 계산보다 훨씬 빠르다.

**이건 우리 수치를 실제로 바꾼다. 다시 계산해야 한다.**
